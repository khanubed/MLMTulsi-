# Rule: Memory Log and Context Tracking

## Objective
Maintain a continuously updated, single source of context in `memory.md` so that all actions, architectural choices, and progress are tracked across interactions.

## Mandatory Actions
1. **Always Update `memory.md`**:
   - Whenever code is written, modified, or deleted.
   - Whenever an architectural or design decision is made.
   - Whenever a dependency or environment configuration changes.
2. **Standard Structure for Updates**:
   - **Timestamp**: Local ISO/human readable time.
   - **Action**: What was executed.
   - **Files Affected**: Clickable file links.
   - **Technical Details**: Rationale, changes, outcome.
   - **Current State & Next Steps**: What is currently working, what is pending.
